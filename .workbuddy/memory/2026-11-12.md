## LuoDeck：F5 整理布局 + 文件夹内图标换位

- **F5 一键整理**：`MainWindow` 里挂窗口级 `QShortcut(Qt::Key_F5)` → `arrangeLayout()`（关掉展开弹层、滚回顶部、调 `AppConfig::autoArrange()`）。展开弹层 `GroupPopup` 里按 F5 也能触发（新增信号 `arrangeRequested`，由 CanvasWidget 接）。右键菜单项改用新 i18n key `canvas.arrange_f5`（「整理布局（F5）」）。
- **文件夹内重排**：`AppConfig::moveChildToIndex(groupId, from, to)`——摘出第 from 项再插到 to，中间顺延，顺序直接写进 `config.json` 的 `children` 数组（`syncDesktopFrame` 只保留已有顺序、新文件追加，所以重排能存活）。
  - 画布上的大框：`GroupItemWidget` 拖动小图标松手时，若仍在框内且落在另一格上就换位；落在框外仍是原来的「拖出变独立图标」。落点用 `IconTile::setDropTarget()` 画虚线框提示。
  - 展开弹层：`GroupPopup` 里同样支持拖到另一格换位，用 `m_tiles` / `m_tileChildIds` 做「格子 → child id」映射（这样带搜索过滤也不串位），重排后就地 `populate()` 重建。
- 桌面框（system）也允许重排，只改显示顺序、不动磁盘文件。
- 编译：`cmd //c "build.bat -nopause"`。**注意**：`bin\LuoDeck.exe` 正在托盘里运行时链接会报 LNK1104，且 `taskkill` 不带 `/F` 杀不掉（closeEvent 里 ignore 后 hide），必须 `taskkill //F //IM LuoDeck.exe`。
- build.bat 跑完后 stderr 里那条 "reg.exe 被安全策略拦截" 是沙箱噪音，不影响构建。

## 修复：隐藏「桌面」框后仍占空间

- 根因：`contentBounds()` / 各处 `occupiedRects()` 都用全量 `m_items`，「桌面」框只是不画，位置照旧算进面板尺寸和空位，于是中间空出一块（当时配置：桌面框 238,16 占 3×2，把文件夹1 挤到 y=180）。
- 修法：
  - `AppConfig::isHiddenItem(it)`（= hide && group && system）、`laidOutItems()`、`laidOutIndexes()`；
  - `contentBounds()` 与 11 处 `occupiedRects(m_items…)` 全部换成 `laidOutItems()`；
  - `pushOverlaps` 遇到隐藏框直接返回；`settleGroup` / `snapAllToGrid` / `load()` 里那次「压在桌面框里的图标」补救都要跳过隐藏框，否则会拿旧坐标把别人挤走；
  - `autoArrange()` 重构为 `packItems(bool sortByName)`：排序版=原逻辑；收拢版按 (y,x) 屏幕顺序摆紧。新增 `reflowLayout()` → `packItems(false)`。
  - `setHideDesktopFrame()` 里直接 `packItems(false)`，取消隐藏时同样收拢一次，免得框压住图标。
  - 老配置迁移：新增 `compactHiddenDone` 标志，若 hide=true 且未收拢过，在 `load()` 里 `packItems(false)` 一次并落盘（避免每次启动都擅自搬家）。
  - 右键菜单加「收拢空位（保持顺序）」（i18n `canvas.compact`）。
- 用 Python 复刻 pack 规则验证当前配置：0 重叠，right=670/bottom=496，原来 3×2 的洞被文件夹3 填上。

## 图标：去掉快捷方式箭头 + 修「图标莫名很小」

- 原因1（小图标）：某些 exe/ico 把图案画在 256 画布的一小块里（实测 PacketTracer 内容只占 57/256），
  按整张缩放画到 40/28 格子里，图案就只剩几像素。
- 原因2（有的有箭头有的没有）：QFileIconProvider 对 symlink（.lnk）会带 `SHGFI_LINKOVERLAY`；
  直接加的 exe/文件夹不带，所以看起来不一致。
- 改法 `src/iconprovider.cpp` 重写：自己调 `SHGetFileInfoW(SHGFI_ICON|SHGFI_SYSICONINDEX)`（**不传 LINKOVERLAY**）
  + `SHGetImageList(SHIL_JUMBO)` 取 256 图标 → `QImage::fromHICON` → `trimAndFit()` 裁透明边后等比撑满 128 存盘。
  需要 `#include <commctrl.h>` 再 `<commoncontrols.h>`（否则 ILD_TRANSPARENT/IMAGELISTDRAWPARAMS 未定义），
  并 `CoInitializeEx` 之后才 `SHGetImageList`。
- 缓存键加了 `|v2` 后缀作废旧 PNG（`cache/icons/` 里老文件不管，只是不再被引用）。
- 验证：新缓存 PacketTracer 内容宽 57/256 → 128/128；VIEW MORE WIDGET 同样填满。

## 启动参数 + 修「打开位置」没反应

- **打开位置没反应的真因**：`Launcher::revealInExplorer` 用 `startSilent("explorer.exe", {"/select,", path})`，
  而 startSilent 会给子进程套 `CREATE_NO_WINDOW` + `STARTF_USESHOWWINDOW/SW_HIDE`——explorer 的窗口被创建成隐藏的，
  所以"点了没反应"；顺带 `/select,` 还被拆成了两个参数。
  改成 COM 官方接口：`CoInitializeEx` → `ILCreateFromPathW` → `SHOpenFolderAndSelectItems`，
  失败再 `QDesktopServices::openUrl` 打开所在目录兜底。需要新 include `<shlobj.h>`、`<objbase.h>`、`<shellapi.h>`。
- **启动参数**：`LayoutItem` 新增 `args`（JSON 里是 `"args"`），`AppConfig::setItemArgs()`；
  右键图标/框内图标 → 「启动参数…」（`QInputDialog::getMultiLineText`，i18n `item.args` / `item.args_prompt`）。
  `Launcher::run(path, args)` 走 `startWithArgs()`（`QProcess::setNativeArguments`，参数整串原样传给 CreateProcess，
  不按空格重新切分）；`.lnk` 先用 `QFileInfo::symLinkTarget()` 解出目标程序再加参数；bat/cmd/ps1/py 分别拼对应命令行。
- `GroupPopup::childLaunchRequested` 信号改成 `(path, args)`；画布里的 `childLaunchRequested` 用 childId 查 config 取 args。
- 参数弹窗不能直接用 `QInputDialog::getMultiLineText`：标题只有"启动参数…"，看不出在改哪个图标，
  提示文字和输入框也很难看清。改成自建 `QDialog`（canvaswidget.cpp `editArgsDialog`）：
  加粗图标名 + 完整路径 + `.lnk` 再补一行「指向：目标」+ 灰色小字说明 + 「启动参数」标签 + 等宽字体 QPlainTextEdit + 中文按钮。
  i18n 新键 `args.label` / `args.hint` / `args.target` / `args.no_target`。
  顺手给 theme.cpp 的输入控件样式补了 `QPlainTextEdit/QTextEdit`（之前没覆盖，深色主题下容易白底或看不清）。

## 支持 Windows 商店 / UWP 应用（Armoury Crate 这类）

- 为什么加不进来：UWP/APPX 在开始菜单里不是 `.lnk`，而是 `shell:AppsFolder` 虚拟目录下的条目，靠 AUMID 启动，没有可拖的文件路径。
- 新增 `src/winapps.cpp/.h`（WinApps 命名空间）：
  - `list()`：`SHGetKnownFolderItem(FOLDERID_AppsFolder)` → `BindToHandler(BHID_EnumItems)` 枚举，
    `SIGDN_PARENTRELATIVEPARSING` 拿 AUMID（含 `!` 才算应用），`SIGDN_NORMALDISPLAY` 拿本地化名字。
  - `image()`：`SHCreateItemFromParsingName("shell:AppsFolder\\<aumid>")` + `IShellItemImageFactory::GetImage` → `QImage::fromHBITMAP`。
  - `activate()`：`IApplicationActivationManager::ActivateApplication`，失败再 `ShellExecuteW("shell:AppsFolder\\<aumid>")`。
  - 内部有个 `ComScope` 负责按需 `CoInitializeEx/CoUninitialize`。
- 新增 `src/winappdialog.cpp/.h`：IconMode 列表 + 搜索 + Ctrl 多选的选择框（列表填充放在 `QTimer::singleShot(0)`，避免开窗卡住）。
- 配置里 path 存成 `shell:AppsFolder\<AUMID>`；`AppConfig::addShellApp(aumid,name,groupId)` 单独走一套（不能复用 addApp，它要 `QFileInfo::exists`）。
- `Launcher::run` / `IconProvider::icon` / `revealInExplorer` 都先判 `WinApps::isShellAppPath`。
- **编译坑**：用 `DeleteObject` 要加 `-lgdi32` 到 LuoDeck.pro 的 win32 LIBS（原来没有，LNK2019）。
- 验证：写了个临时 Qt console 工程跑 `WinApps::list()` → 40 个应用、图标全非空，Armoury Crate = `B9ECED6F.ArmouryCrate_qmba6cd70vzyy!App`（测试工程已删）。

## UWP 图标黑底/倒置 + 标题栏不跟主题

- 图标问题根因：`IShellItemImageFactory::GetImage` 给的是 HBITMAP，之前直接 `QImage::fromHBITMAP`：
  行序被当成自下而上（图标上下颠倒），且 32bpp 的 alpha 常常整块为 0 → 变成不透明黑方块。
  改成自己 `GetDIBits`，`biHeight = -h`（自上而下）+ 检查 alpha 全 0 时退回"纯黑即透明"。
  验证：临时 Qt console 把 15 个 UWP 图标画到深灰画布上存 PNG，确认无黑底、无倒置。
  图标缓存 key 升到 `|v3` 作废旧图。
- 标题栏：`applyFrameTheme()` 之前只设 `DWMWA_USE_IMMERSIVE_DARK_MODE`（20/19），系统会给纯黑标题栏。
  现在额外设 `DWMWA_CAPTION_COLOR(35)` / `DWMWA_TEXT_COLOR(36)` / `DWMWA_BORDER_COLOR(34)`，取主题 surface/text/border。
  给 WinAppDialog（showEvent）、启动参数弹窗、重命名弹窗、首启 QMessageBox 都补了 `winId() + applyFrameTheme()`。

## 深色主题面板变成一片蓝 + 框太圆

- **蓝色根因**：主题 JSON 里写的是 CSS 风格 `#RRGGBBAA`，但 `QColor("#17181CF2")` 按 `#AARRGGBB` 解析：
  α=0x17、颜色=#181CF2（蓝）。`CanvasWidget::paintEvent` 又把 alpha 强制 255 → 满屏蓝。
  修法：`theme.cpp parseColor()` 自己处理 8 位字符串，按 `#RRGGBBAA` 取 r/g/b/a 再 new QColor。
  验证：临时 console 打印 default/dark 的 window 色 → `#f5f6f8`(a=242) / `#17181c`(a=242)，测试工程已删。
- **框更方正**：`Metrics::kGroupRadius` 14 → 6；小文件夹缩略样式 12 → 6（改用 kGroupRadius）；
  展开弹层圆角 14 → 8；框内小图标悬停底色圆角 7 → 4。外层面板仍用主题 radius(12)。
